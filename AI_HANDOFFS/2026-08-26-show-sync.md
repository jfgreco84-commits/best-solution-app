## COMPLETED

### 1. Passed / Not Doing — a stored, reversible show state

Four fields on a show record, set together and removed together:

| Field | Meaning |
|---|---|
| `passed` | `true`. The only value that counts — a truthy string does not. |
| `passedReason` | Why, in the owner's words. Required by the UI. |
| `passedAt` | ISO timestamp the decision was recorded. |
| `passedRevisit` | Optional follow-up for the next application cycle. |
| `passedSource` | `'manual'`, or the `packageId` that set it. |

`isPassed(sh)` is the single predicate. `isMissed()` returns false for a passed
show **before** its date test, so a passed record can never drift into the
Missed tab once its date goes by — that was the specific requirement, and it is
enforced at the lowest level rather than in each view.

**Removed from** (each verified): Upcoming, all three Booking Pipeline buckets
and `oweTotal`, `depositAlerts()`, `calcBoothTally()` owed/due/confirmed counts,
`secBooth()` committed/owed, booked show + show-day + staffed-hour counts,
`rCalendar()` month grid, `exportCalICS()`, `showConflicts()`,
`transferableShows()`, and the pack-inventory action on the show page.

**Deliberately NOT removed:** money already spent. If a booth deposit was paid
before the decision, that cash left the account, and it stays in `calcYTD()`
expenses, in the P&L, and in the booth tally's `paid` figure. `secBooth()` grows
a sunk-cost line naming the amount so it is visible rather than silently folded
in. Dropping it would make the books lie in the owner's favour, which is the one
direction an accounting bug must never go.

**Reversible:** `pndRestore()` deletes exactly the fields `pndMarkPassed()`
added, so a restore returns the record to its previous shape byte for byte —
asserted in the tests and confirmed in the browser.

**Refusals:** a `completed` or `active` show cannot be passed, from either the
UI or a package. A show that was actually worked is history, not a decision.

**UI:** a "🚫 Passed / Not Doing (n)" tab on Shows with an explanatory banner;
an orange PASSED badge that wins over every other badge; a card block showing
the reason, the revisit note, when it was recorded, any sunk booth cost, and a
Restore button; "🚫 Mark Passed / Not Doing" on the show detail page, which
opens a modal that **requires a reason** before it will proceed.

### 2. Apply Show Update Package

New Settings card: **📦 Apply Show Update Package**. Paste or choose a JSON
file, get a full preview, tick one confirmation box, apply.

Against the twelve stated requirements:

1. **Authenticated only through the normal app session.** The feature contains
   no auth code. It reads `_cloudUser`, which the existing Sign In screen sets.
2. **No password touched.** It never asks for, stores, reads or transmits one.
3. **Publishable key + existing RLS.** It does not create a Supabase client, and
   makes no direct Supabase call at all.
4. **Versioned JSON, file or paste.** `format` + `version` are hard gates.
5. **Full preview before writing:** per operation — CREATE / UPDATE / MARK
   PASSED / NO CHANGE, the matched record with its id, *how* it matched, every
   changed field with before and after, duplicate-payment warnings, ambiguous
   matches, and unmatched records.
6. **One explicit confirmation.** A checkbox plus the Apply button; `pkgApply()`
   refuses if the box is not ticked (verified).
7. **Existing save path.** It mutates `S` and calls `saveS()` — localStorage
   then `cloudQueuePush()` under the owner's own session. Identical to every
   other button in the app.
8. **Idempotency key.** `packageId` is recorded in `S._pkgApplied` on success
   and a second apply is refused outright.
9. **No duplicate payments.** A payment is the same payment when it is the same
   money on the same day. Note text is deliberately not part of the test, so
   re-wording a note cannot sneak a duplicate through.
10. **Backup.** The preview screen carries a Download Backup File button above
    the Apply control.
11. **After-apply verification report.** Shows before/after counts, whether
    re-apply is blocked, and whether a re-plan settles to nothing — which is the
    real proof every operation landed. Downloadable as JSON.
12. **No RLS weakening, no service-role bypass.** None exists in the code.

Beyond the requirements, because a `packageId` can go missing exactly the way a
migration marker did in the 2026-08-20 replay, **every operation is
independently self-checking**: a create becomes a match when the show already
exists, a final duplicate refusal sits inside the create path itself, and
marking an already-passed show is a no-op. There is also a **dry run**: the
whole package is applied to a deep clone and re-planned there first, and if it
does not settle, the real state is never touched.

**Matching logic, exactly:**

- Names are normalised with `mrgNormName()` — the same function the replay guard
  uses. It folds en dash, em dash, non-breaking hyphen and minus to `-`, drops
  punctuation, collapses whitespace, lowercases. `Sip & Sleigh — Carol Stream`
  and `sip sleigh - carol stream` are the same show.
- **Primary:** normalised name **and** `startDate` both equal. Exactly one hit
  wins.
- **Secondary:** normalised name alone. Accepted only when unique, and reported
  as a **DATE DRIFT** warning showing both dates, because later migrations
  legitimately move seeded dates.
- **Two or more candidates is never resolved by guessing.** The operation is
  BLOCKED, the whole package becomes unapplyable, and the candidates are listed.
- **Sweep operations** (`nameContains`) list every matched record individually
  by name and date in the preview, and take an `expectMax`. More matches than
  expected blocks the operation, so a broad name rule cannot quietly sweep up an
  unrelated show.
- An optional `location` filter narrows a sweep by normalised substring.

## DECISIONS

1. **Money spent stays spent.** The single most consequential call here. See
   above — passed shows leave every forward-looking total but remain in the
   real-money math, with a visible sunk-cost line.

2. **`isMissed()` excludes passed at the top, not per-view.** One line, and it
   makes "do not label it Missed" true everywhere by construction, including in
   code written later.

3. **Payment method was left blank on both new shows.** The sheet says
   "Not documented. Do not invent one." So there is no method field on either
   payment; instead each payment note and each show's notes say plainly that the
   method is undocumented and needs confirming. Nothing was inferred.

4. **`Rustic Fox 2026` sweep uses `expectMax: 6` against a known set of 4.**
   Enough headroom for a name variant that exists on the live device but not in
   my fixture, low enough that a genuinely over-broad match blocks instead of
   sweeping. The real protection is that the preview names all four matched
   records individually, so an unrelated show would be visible before applying.

5. **Mileage was omitted on the replacement Rustic Fox market** — the sheet does
   not carry it. The show's notes say so and tell the owner to set it in Edit
   Show before relying on gas or IRS mileage figures. A guessed number would
   silently corrupt the mileage deduction.

6. **`APP_VERSION` v32 → v33.** App behaviour changed, which is exactly the
   documented trigger for advancing it.

7. **The package is a data change, not a migration.** No seed was added to the
   HTML. The repo's own replay-guard documentation is explicit that seeding
   shows through a migration is how duplicate identities got minted on
   2026-08-20, and the owner's instruction was not to patch HTML to make the
   interface merely look updated.

- **Phase 2B will now abort if anyone runs it after a package is applied.**

  "Review what the cloud is missing" flow will see an unauthorised field and
  refuse. P2B was a completed one-time operation pinned to fingerprint
  `bb3ca777/86919`, which no longer matches anyway, so it was already going to
  abort — but the failure will now name a different cause. This is
  fail-safe (it changes nothing) rather than a bug, and is recorded here so
  nobody debugs it twice.
